# 05 - 记忆系统

## 概述

Claude Code 的记忆系统通过 `CLAUDE.md` 文件持久化项目上下文，帮助 Claude 在不同会话间保持对项目的理解。

## CLAUDE.md 文件

`CLAUDE.md` 是项目级记忆文件，存储在项目根目录或子目录中，包含：

- 项目概述和架构说明
- 编码规范和风格指南
- 常用命令和工作流
- 重要决策和注意事项
- 项目特定上下文

### 基本结构

```markdown
# 项目名称

## 概述
简要描述项目目的和主要功能。

## 架构
描述项目结构、主要模块和它们的关系。

## 技术栈
- 前端：React + TypeScript
- 后端：Node.js + Express
- 数据库：PostgreSQL

## 编码规范
- 使用 2 空格缩进
- 组件使用 PascalCase
- 函数使用 camelCase
- 导入顺序：外部库 → 内部模块 → 类型

## 常用命令
- `npm run dev` - 开发服务器
- `npm test` - 运行测试
- `npm run build` - 生产构建

## 注意事项
- 不要修改 src/legacy 目录
- 所有 API 调用必须处理错误
```

### 文件加载顺序

Claude Code 按以下顺序加载 CLAUDE.md：

```
1. ~/.claude/CLAUDE.md         - 全局用户偏好
2. 项目根目录/CLAUDE.md         - 项目级配置
3. 当前工作目录/CLAUDE.md       - 子目录配置
4. CLAUDE.local.md             - 本地私有配置（gitignore）
```

### 加载触发

CLAUDE.md 在以下情况下被加载：

- **会话开始时**
- **懒加载** - 当 Claude 进入相关目录时
- **手动刷新** - 使用 `/reload` 命令

## CLAUDE.local.md

`CLAUDE.local.md` 用于存储不应提交到版本控制的私有配置：

```markdown
# 本地配置

## 开发环境
- API 密钥：从 .env.local 获取
- 数据库：本地 PostgreSQL，端口 5432

## 个人偏好
- 使用 VS Code
- 偏好使用调试器而非 console.log
```

**建议：** 将 `CLAUDE.local.md` 添加到 `.gitignore`。

## 多目录支持

### 自动发现

Claude Code 会自动发现当前工作目录及其子目录中的 CLAUDE.md：

```
project/
├── CLAUDE.md              # 根目录配置
├── src/
│   └── CLAUDE.md          # src 特定配置
└── packages/
    ├── api/
    │   └── CLAUDE.md      # api 包配置
    └── web/
        └── CLAUDE.md      # web 包配置
```

### 添加额外目录

```bash
# 启动时添加
claude --add-dir /path/to/other/project

# 会话中添加
/add-dir /path/to/other/project

# 配置中添加
```

```json
// settings.json
{
  "additionalDirectories": [
    "/shared/components",
    "~/common-utils"
  ]
}
```

### 加载额外目录的 CLAUDE.md

默认情况下，`--add-dir` 目录中的 CLAUDE.md 不会被加载。要启用：

```bash
export CLAUDE_CODE_ADDITIONAL_DIRECTORIES_CLAUDE_MD=1
claude
```

## 路径特定规则

在 CLAUDE.md 中使用路径规则来限定某些指令的作用范围：

```markdown
## 路径规则

**src/api/**:
- 所有 API 响应使用 snake_case
- 必须包含错误处理中间件

**src/components/**:
- 使用函数式组件
- 遵循组件命名规范

**tests/**:
- 测试文件以 .test.ts 结尾
- 使用 describe/it 结构
```

## 最佳实践

### 1. 保持简洁

```markdown
# 好的做法 ✅
## 架构
- 采用分层架构：Controller → Service → Repository
- API 路由在 src/api/routes/
- 业务逻辑在 src/services/

# 不好的做法 ❌
## 架构
（大段文字描述，难以快速理解）
```

### 2. 使用结构化格式

```markdown
## API 端点

| 端点 | 方法 | 说明 |
|------|------|------|
| /users | GET | 获取用户列表 |
| /users/:id | GET | 获取单个用户 |
| /users | POST | 创建用户 |
```

### 3. 包含具体示例

```markdown
## 错误处理模式

```typescript
// 使用这个模式
try {
  const result = await service.getData();
  res.json(result);
} catch (error) {
  logger.error('Failed to get data', { error });
  res.status(500).json({ error: 'Internal server error' });
}
```
```

### 4. 定期更新

- 添加新的重要决策
- 更新已变更的架构信息
- 移除过时的内容

### 5. 分离关注点

```
project/
├── CLAUDE.md              # 项目概述、通用规范
├── src/
│   ├── api/
│   │   └── CLAUDE.md      # API 特定规范
│   └── components/
│       └── CLAUDE.md      # 组件特定规范
```

## 示例模板

### Web 项目

```markdown
# 项目名称

## 概述
一个电商网站的前端应用。

## 技术栈
- React 18 + TypeScript
- Vite 构建
- Tailwind CSS
- React Query 数据获取

## 目录结构
```
src/
├── components/     # 可复用组件
├── pages/          # 页面组件
├── hooks/          # 自定义 hooks
├── services/       # API 服务
├── types/          # TypeScript 类型
└── utils/          # 工具函数
```

## 编码规范
- 组件使用函数式 + hooks
- 使用 React Query 管理 API 状态
- 样式使用 Tailwind 类名

## 常用命令
- `npm run dev` - 开发服务器
- `npm run build` - 生产构建
- `npm test` - 运行测试
```

### API 项目

```markdown
# API 服务

## 概述
电商平台的后端 API 服务。

## 技术栈
- Node.js + Express
- TypeScript
- PostgreSQL + Prisma ORM
- Redis 缓存

## API 设计规范
- RESTful 风格
- 响应格式：`{ data, error, meta }`
- 使用 JWT 认证
- 错误使用标准 HTTP 状态码

## 数据库迁移
```bash
npx prisma migrate dev --name description
```

## 环境变量
见 `.env.example`
```

## 初始化 CLAUDE.md

首次在新项目中运行时，Claude Code 会建议创建 CLAUDE.md：

```bash
claude
# Claude 会分析项目并提出创建 CLAUDE.md
```

或手动创建：

```bash
touch CLAUDE.md
# 编辑文件添加项目信息
```
