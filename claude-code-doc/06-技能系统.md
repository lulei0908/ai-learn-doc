# 06 - 技能系统

## 概述

技能（Skills）扩展 Claude Code 的能力，通过创建 `SKILL.md` 文件来定义专业化的指令集。Claude 会在相关场景自动加载技能，也可以手动调用。

## 内置技能

Claude Code 自带以下内置技能：

| 技能 | 说明 | 用法 |
|------|------|------|
| `/batch <instruction>` | 并行执行大规模变更 | `/batch migrate src/ to React` |
| `/claude-api` | 加载 Claude API 参考 | 自动激活或手动调用 |
| `/debug [description]` | 启用调试并分析问题 | `/debug` |
| `/loop [interval] <prompt>` | 定时重复执行提示 | `/loop 5m check deploy` |
| `/simplify [focus]` | 审查并简化代码 | `/simplify` |

## 技能结构

### 基本格式

```
skill-name/
├── SKILL.md           # 必需 - 主技能文件
├── reference.md       # 可选 - 详细参考文档
├── examples.md        # 可选 - 使用示例
└── scripts/
    └── helper.sh     # 可选 - 辅助脚本
```

### SKILL.md 格式

```yaml
---
name: skill-name
description: 技能的简短描述，说明何时使用
---

## 技能指令

在这里详细描述 Claude 应该如何执行这个技能...

### 具体步骤

1. 第一步
2. 第二步
3. 第三步
```

## 创建技能

### 方式一：手动创建

#### 1. 创建目录

```bash
# 个人技能（所有项目可用）
mkdir -p ~/.claude/skills/my-skill

# 项目技能（仅当前项目可用）
mkdir -p .claude/skills/my-skill
```

#### 2. 编写 SKILL.md

```yaml
---
name: deploy
description: 部署应用到生产环境
disable-model-invocation: true
---

# 部署技能

部署应用到生产环境的标准化流程：

1. **运行测试**：`npm test`
2. **构建应用**：`npm run build`
3. **部署**：使用部署脚本
4. **验证**：检查健康检查端点
```

### 方式二：使用 /agents 命令（交互式）

```bash
# 交互式创建（实际上是通过 agents 命令）
/agents
# 选择创建新技能
```

## 技能位置与作用域

| 位置 | 路径 | 作用域 |
|------|------|--------|
| 企业托管 | 托管设置 | 企业内所有用户 |
| 个人 | `~/.claude/skills/<name>/` | 所有项目 |
| 项目 | `.claude/skills/<name>/` | 当前项目 |
| 插件 | `<plugin>/skills/<name>/` | 插件启用范围 |

**优先级：** 企业 > 个人 > 项目 > 插件

## 前置元数据（Frontmatter）

### 完整字段参考

```yaml
---
name: my-skill
description: 技能的描述，说明何时使用
argument-hint: [参数提示]
disable-model-invocation: true
user-invocable: false
allowed-tools: Read, Grep
model: sonnet
effort: high
context: fork
agent: Explore
hooks:
  PreToolUse:
    - matcher: "Bash"
      hooks:
        - type: command
          command: "./validate.sh"
paths: "src/**/*.ts"
shell: bash
---
```

### 字段说明

| 字段 | 类型 | 说明 |
|------|------|------|
| `name` | 字符串 | 技能名称，用于调用 |
| `description` | 字符串 | Claude 决定何时使用的依据 |
| `argument-hint` | 字符串 | 自动补全提示 |
| `disable-model-invocation` | 布尔 | 仅用户可调用，Claude 不会自动加载 |
| `user-invocable` | 布尔 | 是否在 `/` 菜单中显示 |
| `allowed-tools` | 数组 | Claude 可用的工具列表 |
| `model` | 字符串 | 使用的模型 |
| `effort` | 字符串 | 努力级别 (low/medium/high/max) |
| `context` | 字符串 | `fork` 表示在子代理中运行 |
| `agent` | 字符串 | 子代理类型（Explore/Plan/general-purpose） |
| `hooks` | 对象 | 技能特定的钩子 |
| `paths` | 字符串 | 文件路径模式，限定激活范围 |
| `shell` | 字符串 | 执行的 shell (bash/powershell) |

## 字符串替换

### 可用变量

| 变量 | 说明 |
|------|------|
| `$ARGUMENTS` | 所有传入参数 |
| `$ARGUMENTS[0]` | 按索引访问参数 |
| `$0`, `$1`, `$2` | 参数的简写形式 |
| `${CLAUDE_SESSION_ID}` | 当前会话 ID |
| `${CLAUDE_SKILL_DIR}` | 技能目录路径 |

### 示例

```yaml
---
name: create-component
description: 创建 React 组件
---

# 创建组件技能

创建 React 组件，参数格式：组件名 组件类型

组件名：$ARGUMENTS[0]
组件类型：$ARGUMENTS[1]

在 src/components 中创建：
- ${CLAUDE_SKILL_DIR}/template.tsx 作为模板
```

## Shell 命令注入

使用 `` !`<command>` `` 语法在技能执行前运行命令：

```yaml
---
name: pr-summary
description: 总结 Pull Request
context: fork
agent: Explore
allowed-tools: Bash(gh *)
---

## PR 上下文
- PR 差异：!`gh pr diff`
- PR 评论：!`gh pr view --comments`
- 变更文件：!`gh pr diff --name-only`

## 任务
总结这个 Pull Request 的变更...
```

## 在子代理中运行

使用 `context: fork` 在隔离子代理中执行技能：

```yaml
---
name: deep-research
description: 深入研究主题
context: fork
agent: Explore
---

研究 $ARGUMENTS：

1. 使用 Glob 和 Grep 查找相关文件
2. 读取和分析代码
3. 提供包含具体文件引用的总结
```

## 控制调用权限

### 仅用户可调用

```yaml
---
name: deploy
description: 部署到生产
disable-model-invocation: true
---
```

### 仅 Claude 可调用

```yaml
---
name: legacy-context
description: 遗留系统上下文
user-invocable: false
---
```

### 调用权限对照表

| 配置 | 用户可调用 | Claude 可调用 | 何时加载 |
|------|-----------|--------------|---------|
| 默认 | ✅ | ✅ | 描述常驻上下文，完整内容按需加载 |
| `disable-model-invocation: true` | ✅ | ❌ | 完整内容仅用户调用时加载 |
| `user-invocable: false` | ❌ | ✅ | 描述常驻上下文，完整内容按需加载 |

## 工具限制

限制技能内 Claude 可用的工具：

```yaml
---
name: safe-reader
description: 安全读取文件
allowed-tools: Read, Grep, Glob
---
```

## 限制工具使用

在权限设置中限制 Claude 对技能工具的调用：

```json
{
  "permissions": {
    "deny": ["Skill(deploy)"]
  }
}
```

## 故障排除

### 技能不触发

1. 检查描述是否包含用户会说的关键词
2. 使用 `/skills` 查看可用技能列表
3. 直接用 `/skill-name` 调用

### 技能触发过于频繁

1. 让描述更具体
2. 添加 `disable-model-invocation: true`

### 技能数量过多

```bash
# 检查上下文使用
/context
```

## 示例技能

### 代码审查技能

```yaml
---
name: code-review
description: 审查代码质量、安全性和最佳实践
---

# 代码审查技能

## 工作流程

1. 运行 `git diff` 查看变更
2. 重点审查修改的文件

## 审查清单

- [ ] 代码清晰易读
- [ ] 命名规范有意义
- [ ] 无重复代码
- [ ] 适当的错误处理
- [ ] 无暴露的密钥或 API 密钥
- [ ] 输入验证已实现
- [ ] 测试覆盖充分
- [ ] 考虑了性能

## 输出格式

按优先级组织反馈：
- 🔴 关键问题（必须修复）
- 🟡 警告（应该修复）
- 💡 建议（考虑改进）

每个问题包含：
- 问题描述
- 当前代码示例
- 修复建议
```
